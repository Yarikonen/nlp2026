# Лаба 1 — Низкоуровневый анализ, предобработка текста и статистическое языковое моделирование

Курс: анализ текстов (ITMO, 2026). Сквозной датасет — корпус гайдов
[keqingmains.com](https://keqingmains.com) (энциклопедия билдов Genshin Impact).
Скрейпер из предыдущей лабораторной работы скачивает страницы в кеш `raw/*.html`;
для этой лабы датасет — **сырой HTML без какой-либо предобработки**: теги,
скрипты, стили и сущности остаются в данных, вся чистка делается в ноутбуке.

## Структура

```
scrape_kqm.py     скрейпер (переиспользован из RAG-лабы; + utf-8 фикс stdout)
config.json       конфиг скрейпера (125 персонажей, full+quick гайды)
requirements.txt  зависимости (requests/bs4/markdownify — скрейпер; nltk/matplotlib — ноутбук)
lab1.ipynb        вся лабораторная: пп. 1–9 задания, ячейки пронумерованы по шагам
eda_train.png     графики шага 2 (сохраняются при прогоне)
raw/              датасет лабы: сырой HTML из кеша скрейпера (248 страниц)
cleaned/          выгрузка ноутбука: «после» очистки, по одному txt на документ (до/после = raw/<имя>.html <-> cleaned/<имя>.txt)
corpus/           артефакт md-конвертации скрейпера — ноутбуком НЕ используется
catalog.json      кеш каталога сайта из sitemap
manifest.json     статистика скрейпа
```

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -c "import nltk; [nltk.download(p) for p in ('stopwords','wordnet','omw-1.4')]"

.venv/Scripts/python scrape_kqm.py        # скачать/обновить кеш raw/ (повторно не качает)

# ноутбук открыть в VS Code / Jupyter и выполнить сверху вниз,
```

Ноутбук рассчитан на прогон сверху вниз: ячейки шагов 1–9 зависят друг от друга
(токены/словарь/модель переиспользуются).

## Датасет и целевая колонка

* **Документ** — сырая HTML-страница гайда (`raw/<type>-<slug>.html`);
  текстовая колонка — HTML-тело страницы, класс и персонаж — из имени файла.
* **Целевой класс** — префикс имени: `full` (развёрнутый гайд) / `quick`
  (quick-гайд). Статьи `misc` (2 шт.) исключены — класс из двух документов
  не годится для стратификации. Заглушки сайта (57 шт.: «Extended Guide is
  currently in progress / needs an author» или видимый текст < 2000 символов)
  отбрасываются при загрузке.
* Сплит 80/20 со стратификацией вручную (группировка по классу, фикс. зерно 42).

## Что сделано по шагам

1. **Загрузка и сплит**: фильтр заглушек по маркеру и длине видимого текста;
   стратифицированный 80/20, пропорция full/quick сохранена.
2. **EDA (train)**: длины считаются по черновому видимому тексту (теги срезаны,
   сущности ещё нет); количество документов, средние длины в словах/символах,
   гистограммы, топ-30 стоп-слов NLTK.
3. **Шум домена**: два слоя — шум разметки (теги, `<script>/<style>/<svg>`,
   `<head>`, комментарии, каркас `<header>/<nav>/<footer>`, сущности, `<sup>`,
   href/src-атрибуты) и шум содержимого (changelog-строки, повторяющиеся
   извещение и cookie-хвост, `@ники` художников, URL, игровые числа, ★♠♥);
   markdown/бэктики/экранирования отсутствуют по построению.
4. **Конвейер очистки на `re`**: 23 правила, порядок важен — сначала целые
   блоки, потом теги→переводы строк (текст заголовков и ячеек таблиц
   сохраняется), потом декодирование сущностей и текстовые правила:
   changelog-строки и списки правок целиком, извещение и cookie-хвост по
   маркерам, URL → `[URL]`, числа → `[NUM]`; в конце обёртка `<s> … </s>`.
   Каждый документ выгружается парой «до/после»: `raw/<имя>.html` ↔
   `cleaned/<имя>.txt`.
5. **Нормализация**: стемминг Портера vs лемматизация WordNet, сравнение размеров
   словарей + коллизии стеммера.
6. **Левенштейн**: реализация с двумя строками DP (память O(min(|a|,|b|))) и
   ранним выходом по порогу; пары слов train с d=1..2, топ-10.
7. **N-граммная модель**: биграмма и триграмма, явный словарь (freq ≥ 2),
   `[UNK]` для редких/OOV, счётчики всех порядков 1..n.
8. **Сглаживание и перплексия**: MLE без сглаживания (P=0 → PPL=∞), Лаплас
   add-1, линейная интерполяция Jelinek–Mercer; PPL через log-likelihood.
9. **Генерация**: 5 текстов Марковской цепью (триграммная модель,
   интерполяционное распределение), старт `<s>`, стоп `</s>`/40 токенов.

## Результаты

Все числа — из финального прогона `lab1.ipynb` (seed 42); там же графики и примеры.

**Сплит (п. 1).** Из 248 скачанных страниц после фильтров — 189 документов
(68 full / 121 quick, 56.5 млн символов сырого HTML), 57 заглушек отброшено.
Train 151 (54 full / 97 quick), test 38 (14 / 24); доля full 35.8% в train
против 36.8% в test — стратификация пропорцию сохранила.

**EDA на train (п. 2).** Средняя длина видимого текста 7 845 слов / 48 093
символов, медиана 6 612 / 39 788, разброс 1 787–38 289 слов — правый хвост
делают развёрнутые full-гайды. Встречено 160 разных стоп-слов NLTK, топ-30
покрывают 78% всех стоп-словных употреблений (`the`, `a`, `to`…).
Графики: `eda_train.png`.

**Шум (п. 3).** Разметка (train, сырой HTML): теги 495 259, блоки `<script>`
3 935 и `<style>` 1 538, `<svg>` 2 416, комментарии 1 904, каркас
`<header>/<nav>/<footer>` 658, сущности 24 908, сноски `<sup>` 948, атрибуты
href/src 39 819. Содержимое (видимый текст): числа/скейлы 32 643, ★♠♥ 1 269,
changelog 147, извещение «Please link this guide…» и cookie-хвост — по 151
(на каждом документе), `@ники` художников 71, сырые URL 22. Markdown, бэктики
и экранирования — 0 (6 литеральных `**` в тексте — не разметка).

**Очистка (п. 4).** 23 правила, 189 документов за ~5 с. Топ срабатываний:
блочные теги → `\n` 202 761, остальные теги 187 650, `→ [NUM]` 36 598, ячейки
таблиц → пробел 26 313, сущности 18 192 + 4 506. После очистки: 1 158 802
токенов, словарь 12 867 типов; самый частый токен — `[NUM]` (36 598), т.е. вся
«числовая» разметка корпуса схлопнулась в один служебный токен.

**Нормализация (п. 5).** Словарь 12 867 → стемминг Портера 8 724 (67.8%),
лемматизация WordNet 10 138 (78.8%). Стеммер схлопывает сильнее, но ценой
коллизий (general/generally/generate → `gener`) и нечитаемых форм
(`charact`, `enemi`, `damag`); лемматизация бережнее и слова сохраняет.

**Левенштейн (п. 6).** 5 547 слов (freq ≥ 5, длина ≥ 4), 22 404 пары с d ≤ 2
(2 470 с d = 1), перебор 41 с. Топ-10 пар — словоформы (`team/teams`,
`attack/attacks`, `rotation/rotations`, `teams/team's`) и несколько пар похожих
частотных слов (`than/that`, `skill/still`, `well/will`). Целевой профиль опечатки
(редкое freq≤2 на d=1 от частого freq≥20, без записи в WordNet): 1 136 пар,
180 кандидатов — настоящие опечатки есть (`skil`, `ehen`, `dedro`, `xinqiu`,
`rcommended`, `favonis`), плюс доменный сленг (`stronk`, `damager`).

**Модель (п. 7).** Словарь 9 099 типов (freq ≥ 2 + `[UNK]`; доля `[UNK]`
в train-позициях 0.33%). Уникальных биграмм 236 628, триграмм 625 484.

**Перплексия на test (п. 8)**:

| модель | без сглаживания | Лаплас add-1 | интерполяция |
|---|---|---|---|
| биграмма N=2 | ∞ | 517 | **132** |
| триграмма N=3 | ∞ | 2 573 | **95** |

**Генерация (п. 9).** 5 текстов триграммной моделью с интерполяционным
распределением, старт `<s>`, стоп `</s>` или 40 токенов — тексты в
lab1.ipynb (шаг 9).

## Выводы

1. **Корпус** — длинные технические тексты с тяжёлым правым хвостом по длине;
   quick-гайды компактнее full-гайдов, но лексика та же, поэтому класс
   «full/quick» по тексту почти не разделяется тривиальными статистиками.
2. **Шум веб-корпуса двухслойный**: разметка (полмиллиона тегов, скрипты,
   стили, каркас — 56.5 МБ HTML против ~7 МБ текста) и повторяющийся
   бойлерплейт содержимого (извещение и cookie-хвост на каждой из 189
   страниц, `@ники` художников). Каждому типу шума — отдельное правило;
   «удалить всё, кроме букв» недопустимо: текст таблиц и заголовков несёт
   смысл и сохраняется через теги→границы строк.
3. **Нормализация**: стемминг даёт лучшее сжатие словаря (−32% против −21%),
   но порождает коллизии и нечитаемые основы; лемматизация консервативнее
   и для дальнейшей LM/анализа предпочтительнее, стемминг — там, где важна
   экономия словаря (поиск, IR).
4. **Строковые метрики**: пары с d ≤ 2 в чистом редакторском корпусе — это почти
   целиком морфологические варианты, а не опечатки; сам по себе критерий
   «расстояние ≤ 2» не отделяет ошибку от словоформы — нужны частотные и
   словарные фильтры.
5. **Сглаживание математически необходимо**: без него правдоподобие теста
   обнуляется (PPL = ∞) из-за невиденных n-грамм. Add-1 Лапласа раздаёт массу
   ~V = 9 099 каждому невиденному событию, поэтому штраф тем сильнее, чем
   разреженнее порядок: триграмма (2 573) хуже биграммы (517). Линейная
   интерполяция Jelinek–Мерсера смешивает порядки и лучшая в обоих случаях;
   итоговая модель — интерполированная триграмма, PPL = 95.
6. **Генерация**: тексты локально правдоподобны (доменные клише `charged
   attack`, `plunging attack`, имена персонажей/артефактов, `[NUM]` на месте
   цифр), но глобально бессвязны — тема меняется каждые несколько токенов,
   изредка проскакивает `[UNK]`. Ожидаемое поведение цепи Маркова: короткие
   зависимости есть, дальних нет.
